🌿 CollabSphere

A cross-house and regional meetup engine for IITM BS students.
Find peers near you, co-host meetups across houses, and prove you showed up.

Live: collabsphere-one.vercel.app · Code: github.com/arshanalikhan/collabsphere
By Arshan Ali Khan

The problem

  • IITM BS students are spread across cities and countries, so in-person meetups are rare and hard to organise.
  • Cross-house events run on WhatsApp threads and Google Forms, with no shared calendar and no approval trail.
  • Nobody can verify who actually attended, so showing up earns no recognition for the student or their house.

What CollabSphere does

🗺️ Regional map

Live meetups and co-working sessions as pins, plus students as one bubble per city (counts only, so locations stay private).

🤝 Joint-event host manager

Propose events with co-host houses and partner societies. An event goes live only when every host house approves.

📍 Proof of presence

Rotating signed QR (30 s), 500 m geofence, one check-in per person, optional in-browser liveness face check.

🏆 Recognition

House points and leaderboard, top members, profile badges and attendance history.

The full event lifecycle

  1. Coordinator proposes an event (venue from GPS, co-host houses, partner societies)
  2. An admin from every host house approves; then it appears on the map
  3. Students RSVP, add it to Google Calendar / .ics, share on WhatsApp, get directions
  4. On the day: host shows the rotating QR, attendees scan it at the venue
  5. Points go to the house; admins export attendance and can revoke check-ins

Admin workflows

  • Approvals queue showing which host houses have approved
  • Events: inline edit (title, venue, IST time, points, face check, partners), cancel / restore
  • Attendees per event with one-click CSV export
  • Members: roles, moving between houses, point adjustments
  • Check-in audit with selfie thumbnails; revoking reverses the points
  • Every admin sees and manages only their own house

Technical architecture

Next.js 15 App Router

Server Components read MongoDB directly; Server Actions for admin and profile; Route Handlers for the JSON, .ics and CSV APIs.

Data & auth

MongoDB Atlas + Mongoose with 2dsphere geo queries. Auth.js Google sign-in limited to IITM domains, roles and house scoping on every route.

Security

HMAC-signed rotating QR, geofence, idempotent approvals, input validation, privacy-rounded locations, 30-day selfie purge.

Quality

Unit tests + a 37-check end-to-end lifecycle test, run in GitHub Actions CI on every push.
